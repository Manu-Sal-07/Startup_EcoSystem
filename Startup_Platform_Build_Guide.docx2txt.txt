Phase 3 Prompt

🤖 AGENTIC PROMPT — PHASE 3 — Core API Routes

TASK: Complete Phase 3 — All FastAPI routes with Neo4j + Redis cache-aside pattern.



CACHE-ASIDE PATTERN (apply to EVERY GET endpoint):

  1. Check Redis: result = cache_get(key)

  2. If HIT: return result immediately (<1ms)

  3. If MISS: query Neo4j, store in Redis with TTL, return result



Step 1 — Create backend/routes/startups.py:

  POST /startups/register

    - Validate with Pydantic, generate UUID

    - Neo4j: CREATE (:Startup {id, name, sector, stage, funding_ask,

      equity_offered, pitch, team_size, revenue, founded, created_at: datetime()})

    - Redis: setex('profile:startup:{id}', 600, json)

    - Redis: delete('feed:filtered:*') to invalidate feeds

    - Trigger matching engine async

  GET /startups/{id}  — cache TTL 600s

  GET /startups/feed?sector=&stage=&min_ask=&max_ask=

    - Hash filter params to create Redis key: feed:filtered:{hash}

    - Cache TTL 120s

  GET /startups/{id}/viewers  — read from Redis views:startup:{id} hash

  GET /startups/{id}/matches  — cache TTL 300s (from matching engine)



Step 2 — Create backend/routes/investors.py:

  POST /investors/register

    - CREATE (:Investor {id, name, firm, type, ticket_min, ticket_max,

      preferred_sectors, stage_focus, bio, created_at: datetime()})

    - Redis: cache profile 600s, add to leaderboard sorted set score 0

  GET /investors/{id}  — cache TTL 600s

  GET /investors/{id}/matches  — cache TTL 300s

  POST /investors/{id}/view/{startup_id}

    - ONLY Redis: hset('views:startup:{startup_id}', investor_id, timestamp)

    - NO Neo4j write — maximum speed



Step 3 — Create backend/routes/connections.py:

  POST /connect/interest  — body: {investor_id, startup_id, message, proposed_amount}

    - Neo4j: CREATE [:INTERESTED_IN {message, proposed_amount, status:'pending', date: datetime()}]

    - Redis: delete profile caches for both parties

    - Redis: zincrby('leaderboard:investors', 1, investor_id)

  POST /connect/accept  — body: {investor_id, startup_id}

    - Neo4j: SET r.status='accepted', r.accepted_at=datetime()

    - Neo4j: CREATE [:CONNECTED_TO {date: datetime()}]

    - Redis: update leaderboard, re-cache profiles

  POST /connect/reject  — SET status='rejected' only

  GET /connections/{startup_id}  — cache 60s



Step 4 — Create backend/routes/analytics.py:

  GET /analytics/network  — ALL nodes + edges for D3.js, cache 300s

  GET /analytics/leaderboard  — read Redis sorted set zrevrange top 20

  GET /analytics/sector-trends  — group by sector, sum funding, cache 300s

  GET /analytics/hot-sectors  — INTERESTED_IN edges last 30 days, cache 120s

  GET /analytics/influence  — 2-hop degree centrality per node, cache 600s



Verify each endpoint manually with curl or browser.







Phase 4 Prompt

🤖 AGENTIC PROMPT — PHASE 4 — Smart Matching Engine

TASK: Complete Phase 4 — Graph-powered matching algorithm using Neo4j Cypher.



Create backend/matching.py with function: compute_matches(startup_id) -> List[dict]



Step 1 — Full matching Cypher query (4 components, max 100 points):

  MATCH (i:Investor), (s:Startup {id: $startup_id})

  WITH i, s,

    CASE WHEN s.sector IN i.preferred_sectors THEN 40 ELSE 0 END AS sector_score

  WITH i, s, sector_score,

    CASE

      WHEN i.ticket_min <= s.funding_ask AND s.funding_ask <= i.ticket_max THEN 30

      WHEN i.ticket_min <= s.funding_ask * 1.2 THEN 15

      ELSE 0

    END AS ticket_score

  WITH i, s, sector_score, ticket_score,

    CASE WHEN s.stage IN i.stage_focus THEN 20 ELSE 0 END AS stage_score

  OPTIONAL MATCH path = (i)-[:INVESTED_IN*1..2]->(other:Startup)

  WHERE other.sector = s.sector

  WITH i, sector_score, ticket_score, stage_score,

    CASE WHEN count(path) > 0 THEN 10 ELSE 0 END AS network_score

  WITH i, (sector_score + ticket_score + stage_score + network_score) AS total_score

  WHERE total_score > 0

  RETURN i.id, i.name, i.firm, i.type, total_score,

    sector_score, ticket_score, stage_score, network_score

  ORDER BY total_score DESC LIMIT 10



Step 2 — Mirror function: compute_matches_for_investor(investor_id) -> List[dict]

  Same logic but MATCH (s:Startup), return startups ordered by score



Step 3 — Cache management:

  - After computing: cache_set('matches:startup:{id}', results, 300)

  - Invalidate on: new bid received, new startup in same sector



Step 4 — Wire into routes:

  - After POST /startups/register: run compute_matches(new_id) in background

  - After POST /investors/register: run compute_matches_for_investor(new_id)

  - After POST /connect/interest: invalidate matches for both parties



Step 5 — Test with 3 scenarios:

  a) FinTech Seed startup $500K ask — should match FinTech-focused Seed investors highest

  b) AI/ML Series A startup $5M ask — should match VC firms with high ticket sizes

  c) Startup in sector where investor has existing portfolio — network_score = 10







Phase 5 Prompt

🤖 AGENTIC PROMPT — PHASE 5 — Three-Tab Frontend Dashboard

TASK: Complete Phase 5 — Full frontend dashboard in frontend/index.html.

Use only vanilla HTML, CSS, JavaScript + D3.js v7 + Chart.js (CDN links).

DO NOT use any frameworks. Single file only.



Step 1 — Layout structure:

  <div class='tab-bar'> with 3 buttons: Startup | Investor | Analyst

  <div id='tab-startup'>, <div id='tab-investor'>, <div id='tab-analyst'>

  Active tab shown, others hidden. CSS: clean white cards with box-shadow.



Step 2 — Tab 1 (Startup Dashboard):

  Panel A: Registration form (name, sector dropdown, stage, funding_ask, equity,

    pitch textarea, team_size, revenue, founded) → POST /startups/register

  Panel B: My Profile Card (loads after register, shows all fields)

  Panel C: Who Viewed Me (polls GET /startups/{id}/viewers every 10s)

    Shows investor name + timestamp for each view

  Panel D: My Best Matches (GET /startups/{id}/matches)

    Show top 10 investors as cards with score bar (0-100) + breakdown

  Panel E: My Connections (GET /connections/{id})

    Show pending/accepted/rejected bids with investor details



Step 3 — Tab 2 (Investor Dashboard):

  Panel A: Registration form (name, firm, type dropdown, ticket_min, ticket_max,

    preferred_sectors checkboxes, stage_focus checkboxes, bio)

  Panel B: Filter Panel → GET /startups/feed

    Sector multi-select, stage dropdown, funding range slider

  Panel C: Startup Feed Cards

    Each card: name, sector badge, stage, ask, pitch snippet

    Buttons: [View Profile] (POST view) + [Express Interest] (modal with message)

  Panel D: My Matches (GET /investors/{id}/matches)



Step 4 — Tab 3 (Analyst Dashboard):

  Row 1: Stats bar — Total Startups | Total Investors | Total Connections | Hot Sector

    Fetch from GET /analytics/sector-trends and /analytics/network

  Row 2: D3.js Force Graph (GET /analytics/network)

    Blue circles = Startups, Red circles = Investors, Green = Founders

    Edge thickness = investment amount (normalized)

    Edge color: INTERESTED_IN=orange, CONNECTED_TO=green, INVESTED_IN=blue

    Hovering node shows tooltip with name + sector/firm

  Row 3: Chart.js Bar Chart — Sector Funding (GET /analytics/sector-trends)

  Row 4: Investor Leaderboard table (GET /analytics/leaderboard) — top 20

  Row 5: Hot Sectors (GET /analytics/hot-sectors) — last 30 days activity



Step 5 — Cache indicator badges:

  All API responses include header or body field: {source: 'redis'|'neo4j', ms: N}

  Show green badge '⚡ Redis <1ms' or blue badge '🔵 Neo4j Xms' on each panel



Final: Open frontend/index.html in browser (no server needed for frontend).

All API calls go to http://localhost:8000 — ensure CORS is enabled on FastAPI.
